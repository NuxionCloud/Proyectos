1Overview

Bot conversacional de WhatsApp para Bocatitos Street Food, un local de Av. Sánchez Pizjuán 6 (Distrito Macarena, Sevilla). El cliente final escribe al bot por WhatsApp y este le guía con un menú interactivo para consultar la carta, ver horarios, ver cómo llegar y hacer un pedido. El pedido finalizado se reenvía al móvil del restaurante para que se procese manualmente y pase a cocina.

El bot vive en el servidor n8n de Manu (productivo Nuxion) y usa Twilio WhatsApp Sandbox como pasarela. Para producción real con el cliente se migra a Meta Cloud API directo con el número del cliente — el código del workflow es ~90% reutilizable.

Estado actual: Demo funcionando end-to-end. Solo accesible para los 5 móviles verificados en el sandbox de Twilio (limitación del trial). Suficiente para enseñar a los socios y al cliente.

  • Acceso al n8n productivo de Manu.

4Reglas de oro

★ Regla 1 — TwiML por defecto. Para respuestas síncronas al cliente, usa TwiML (XML) devuelto por el nodo "Respond to Webhook" en lugar de hacer una llamada extra a la API de Twilio. Más rápido, más simple, una sola petición de red.
★ Regla 2 — Estado por WaId. Cada cliente en WhatsApp tiene un WaId único (su número). Indexa el carrito y cualquier estado de sesión por ese ID — nunca por el nombre o el From.
★ Regla 3 — Sin async largo en el handler. Twilio espera respuesta en menos de 5 segundos o reintenta. Cualquier lógica pesada (LLM, lookup en DB grande) se ejecuta fuera del flujo síncrono (publish a queue, respond ack ahora, procesar después).
★ Regla 4 — Sandbox solo para desarrollo. Twilio Sandbox limita a 5 destinatarios verificados y muestra prefijo "Sent from your Twilio trial account" en mensajes. Para producción real: migrar a Meta Cloud API directo con número del cliente.
★ Regla 5 — Sticky notes en n8n. Todo workflow debe tener un sticky note general explicando el flujo + uno por bloque funcional (regla Nuxion). Facilita que cualquier socio entienda el workflow sin pedir contexto.

5Procedimiento paso a paso

1.Crear cuenta Twilio y activar Sandbox

  1. Registro en twilio.com/try-twilio.
  2. Elegir plan Trial (no Pay as you go).
  3. Ir a Messaging → Try it out → Send a WhatsApp message.
  4. Apuntar el código join <palabra> que aparece en la pantalla del sandbox.

2.Suscribir tu móvil al sandbox

  1. Abrir WhatsApp en el móvil.
  2. Iniciar chat con +1 415 523 8886.
  3. Enviar el mensaje exacto join <palabra> (el código del paso 1).
  4. Twilio responde con un "You are all set!" confirmando.

3.Capturar credenciales

En el Twilio Console, ir a Account → API Keys & tokens:

  • Account SID: visible directamente.
  • Auth Token: pulsar "Show" para revelarlo. Guardar en gestor de contraseñas.
El Auth Token es secreto. Nunca pegarlo en chats, código público o capturas. Si se filtra, ir a "Request a secondary token" en el mismo panel para rotarlo.

4.Crear workflow en n8n

En el n8n productivo de Manu:

  1. Nuevo workflow: nombre [Bocatitos] Bot WhatsApp Sandbox - Twilio.
  2. Nodo 1: Webhook (typeVersion 2.1).
    • Method: POST
    • Path: bocatitos-twilio
    • Authentication: None
    • Respond: Using 'Respond to Webhook' Node
    • onError: continueRegularOutput
  3. Nodo 2: Code (typeVersion 2) con el JS del cerebro del bot (ver Anexo A).
  4. Nodo 3: Respond to Webhook (typeVersion 1.5).
    • Respond With: Text
    • Response Body (expresión): =<?xml version="1.0" encoding="UTF-8"?><Response><Message>{{ $json.reply }}</Message></Response>
    • Response Code: 200
    • Header: Content-Type: application/xml
  5. Conectar Webhook → Code → Respond.
  6. Activar el workflow (toggle "Active" arriba a la derecha).
  7. Copiar la Production URL del nodo Webhook.

5.Configurar webhook en Twilio

  1. En Twilio Console, ir a Messaging → Try it out → Send a WhatsApp message → Sandbox settings.
  2. En When a message comes in: pegar la Production URL del paso 4.
  3. Method: POST.
  4. Pulsar Save.

6Workflow diario

Una vez todo configurado, las modificaciones del bot son siempre las mismas:

  1. Abrir el workflow en n8n.
  2. Editar el nodo "Procesa Intent" (es donde vive toda la lógica).
  3. Probar con "Execute Node" usando un payload de ejemplo.
  4. Guardar.
  5. El workflow ya está activo: la siguiente llamada de Twilio usa el código nuevo.

Para añadir productos nuevos a la carta: editar el objeto PRODUCTS en el Code node, sumar el nombre + precio. Los aliases (mensaje libre) van en el objeto ALIASES.

7Troubleshooting

Carrito se "olvida" entre mensajes Workflow desactivado entre mensajes (Static Data se pierde al desactivar) Mantener workflow siempre activo. En prod usar DB externa (Supabase)
El mensaje aparece truncado en WhatsApp Caracteres no escapados en XML Usar <, >, & escapados en el reply (n8n lo hace automático con expresión)
Detección de productos falla Nombre del producto con tildes/eñes que no matchean el regex Añadir alias en minúsculas y sin tildes en el objeto ALIASES
Twilio Sandbox da timeout Code node tarda >5 segundos Optimizar regex o externalizar lógica pesada a queue

8Lessons learned (changelog)

v2.0 · 2026-06-03

  • Decisión: Twilio Sandbox elegido sobre Meta Cloud API directo. Meta cambió el flujo en 2025 y dejó imposible añadir el producto "WhatsApp Business" a apps nuevas vía UI. Los permisos whatsapp_business_messaging no aparecen en Graph Explorer ni al generar System User token. Twilio Sandbox lo evita por completo.
  • Lección: para demos de bots WhatsApp, Twilio Sandbox es 10× más rápido de montar que Meta directo. Para producción real, migrar a Meta con número del cliente.
  • Hallazgo: TwiML como respuesta sincrona es mucho más simple que llamar a la API de Twilio. Una sola petición de red, sin gestionar Auth Token en HTTP Request.
  • Hallazgo: $getWorkflowStaticData('global') sirve para carrito de demo. En producción usar Supabase o DataTables — Static Data se pierde al desactivar el workflow.
  • Hallazgo: detección de productos por regex con ordenación por longitud descendente (matchear primero "patatas bravas" antes de "patatas") funciona bien para la lista corta de Bocatitos.

v1.0 · 2026-06-03 (mismo día)

  • Primer prototipo: menú principal + 6 categorías + horario + dirección.
  • Sin carrito persistente, solo eco del mensaje.

9Migración a Meta Cloud API en producción

Cuando Bocatitos confirme el contrato, migrar de Twilio Sandbox a Meta Cloud API directo:

  1. Pedir al cliente número dedicado al bot (no su número personal). Vodafone/Yoigo prepago ~5€.
  2. Crear Facebook Business Manager con la identidad del cliente (no la nuestra).
  3. Crear app de tipo "Empresa" en developers.facebook.com.
  4. Vincular WhatsApp Business Account con el número del cliente.
  5. Generar System User Token permanente con permisos whatsapp_business_messaging.
  6. Modificar el nodo final del workflow: en lugar de "Respond to Webhook" con TwiML, usar HTTP Request POST a https://graph.facebook.com/v21.0/{PHONE_NUMBER_ID}/messages con Bearer token.
  7. Suscribir webhook al campo messages en el panel WhatsApp de la app.
  8. El resto del Code node (intent + carrito) se reutiliza tal cual.

Estimación: 1-2 horas de trabajo si Meta no pone trabas con la app del cliente.
